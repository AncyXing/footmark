    系统分析与设计方法

    # 基本原则

    将业务抽象为软件领域元素（系统、模块、类），定义元素的边界，隐藏实现开放接口。

    # 系统开发设计的一般方法

    • 需求分析
    • 概要设计
    • 详细设计
    • 编码实现
    • 测试

    # 需求分析

    针对业务需求进行建模，输出系统的逻辑设计与结构，让别人可以清楚知道系统是做什么的，包含哪些内容以及如何运转的。 产出包括：

    • 需求用例（用于理清业务需求），解决是什么的问题，明确what
    • 将业务对象抽象成实体模型（确定系统包含的实体，以及实体之间的关联关系），确定参与者的范围，明确who。
    • 业务场景的交互流程和状态转换（确定具体业务场景中，参与者的交互过程），明确how

    # 概要设计

    概要设计需要考虑系统在整体上下文中的位置和与其他系统的关联关系，明确每个系统的职责。确定系统内部的功能模块及其职责，系统模块划分有业务功能的划分、基于实现层次的划分。 产出包括：

    • 定义系统职责
    • 系统间的交互图，数据流转
    • 拆分出模块，明确模块的职责
    • 模块间的交互图，数据流转
    • 接口的定义，输入输出
    • 实体关系图（描述有哪些实体及实体间的关系）

    # 详细设计

    对每个模块的功能进行具体的描述，产出包括：

    • 具体功能的流程图
    • 接口的具体实现逻辑
    • 表结构及字段、阐述表名、字段名、字段类型

    # 系统设计的中的视图：

    • 逻辑视图：对应概要设计
    • 开发视图：对应详细设计
    • 过程视图：对应概要设计和详细设计
    • 物理视图：描述如何部署实施，对应概要设计和详细设计
    • 场景视图：对应需求分析

    其中场景视图为4+1中的1

    # 明确关注点

    综合各种架构视角，对关注点进行取舍

    • 安全性
    • 性能
    • 稳定性
    • 扩展性
    • 其他

    # 总结

    • 先进行概要设计，之后详细设计可以分系统分模块并行进行。
    • 概要设计需要多次打磨，多次拆分或多次合并，对应于多次抽象和多次封装，最终清晰的界定边界和职责。
    • 详细设计的变更也要及时反应到概要设计中。
